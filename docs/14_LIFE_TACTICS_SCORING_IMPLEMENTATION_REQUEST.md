## 기본 문항과 전술

기존 18개 응답의 Options.ScoreValue(1~5)를 사용합니다. Questions.Reverse가 true이면 6−응답값을 한 번 적용합니다. 문항별 점수는 (보정값−1)×25, 축별 점수는 가중합/해당 축 가중치 합입니다. 기존 quiz_engine과 Python 계산에서 이미 처리하는 부분은 재사용하고 UI에서 중복 반전하지 마세요. 순서·표시 번호 대신 ID로 답을 저장합니다. 각 축은 정방향 5개와 역방향 1개입니다. 기존 10전술의 RuleSets와 RuleMappings를 사용하고 비교 전 반올림하지 마세요. 모든 문항에 4번이면 각 축 200/3점과 tr10입니다. 전체 4번의 균형 판정을 억지로 해소하는 목적이 아닙니다.

## 상황 선택의 복합 배점

0.5.0 / scenario_v2는 6개 상황에서 3개 행동 중 하나씩 고릅니다. QuestionData.xlsx의 ScenarioOptionScores 기본키는 QuizId, BaseDataVersion, PilotVersion, ScenarioId, OptionId, DimensionId의 조합입니다. Points는 0 이상의 정수입니다. 같은 버전의 ScenarioOptions 및 Dimensions와 연결합니다. DimensionId를 새 진단별 열로 늘리지 않습니다. v2에서는 옵션당 세 축 모두 명시하고 점수 순열은 2·1·0입니다. ScenarioOptions.DimensionId는 주축이며 2점 축과 일치해야 합니다. 현재 버전별 파일럿 정책으로 검증하고 공통 집계기는 축과 점수를 데이터에서 읽습니다.

tools/data/lookatyou/workbook.py, validate.py, serialize.py 및 scenario.py부터 확인하세요. v2 시트 누락, 중복 키, 없는 축·옵션, 버전 혼합, 일부 축 누락, 음수·소수·빈칸, 합계 또는 주축 불일치, 필수 한국어 키 누락을 오류 처리합니다. 0점과 누락을 구분합니다. v1은 기존 산출물을 유지합니다. v2 JSON에는 파일럿 단위 scoringMode=option_points, 옵션별 pointsByDimension 맵을 출력합니다. 예를 들어 첫 장면의 첫 선택은 happiness=2, meaning=1, richness=0입니다. 미지원 모드나 손상된 v2는 오류를 표시하고 단일 축 횟수로 대체하지 마세요. 확인된 데이터만 기존 publish 경로로 생성합니다.

app/lib/features/catalog의 모델·디코더·저장소, quiz_scenario.dart의 세션과 집계, ui_preview.dart, pubspec.yaml을 연결합니다. 현재 기본 버전과 scenario_v1.json 경로 및 pilot 조회 기본값을 함께 확인하세요. 새 미리보기에서 0.5.0/scenario_v2를 열고 재개 시 원래 버전으로 조회합니다. 장면당 최종 답 하나만 인정하고 변경·뒤로가기 후 전체 응답에서 다시 합산합니다. 6개 완료 시 세 축 합계 18점입니다. 18개 기본 문항 점수만 10전술 판정에 사용하고, 결과 카드에 상황 점수는 별도로 표시합니다. 2축 공동 1위는 두 축, 3축 동점은 균형으로 표시합니다. 이 점수는 상황 속 상대적 선택을 뜻합니다. ## Cursor가 실행할 검증과 완료 기준

1. 루트에서 python tools/data/validate.py, python tools/data/build.py, python -m unittest discover -s tools/data/tests 실행. 새 버전은 preview에만 등록하고 기존 release 제외 조건을 유지합니다. 수정 전후 구버전 번들과 기존 회귀 사례를 비교하세요.
2. Flutter와 Python에서 같은 입력을 사용합니다. 역문항 응답 1·2·3·4·5의 보정값은 5·4·3·2·1입니다. 정방향 전체 5/역방향 전체 1은 세 축 100, 반대는 세 축 0입니다. 0.4.0의 모두 4는 세 축 75입니다.
3. v2 응답 729조합 각각에 대해 두 언어의 축 점수·합계·공동 선두가 같은지 검사합니다. 각 장면의 1번만 선택하거나 2번만 또는 3번만 선택하면 각각 (6,6,6)입니다. 매번 행복 주축을 선택하면 (12,3,3)입니다. 0.4.0은 기존 횟수 합계 6입니다. 응답 변경·미완료·다른 장면 옵션·중복 응답·잘못된 데이터·파일 누락과 이전 회차 복원도 검사합니다.
4. app에서 flutter pub get, flutter analyze, flutter test, flutter run -d chrome을 실행합니다. Chrome에서 18+6 완주, 결과 화면의 두 단위, 응답 변경, 한국어 폴백을 확인합니다. 새 JSON과 애셋 등록까지 커밋 대상에 포함합니다. 실행한 명령·통과 수·실패·미실행 항목을 보고해 주세요.
