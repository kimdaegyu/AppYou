# Cursor 개발 요청서 · 나의 인생 전술

D:\AppYou에서 기존 Excel 직렬화 도구와 Flutter 카탈로그를 확장해, 개발 미리보기에서 응답 → 점수 → 결과 ID까지 연결해 주세요. 아래 추천값으로 구현과 검증을 시작할 수 있습니다. 출시 승인과 문항의 최종 편집은 별도 결정입니다.

## 1. 시작점과 검토 자료

- AGENTS.md, 01_PRODUCT, 02_ARCHITECTURE, 03_DATA_SCHEMA, 07_DECISIONS, app/pubspec.yaml과 작업 트리의 사용자 변경을 먼저 확인합니다. 데이터 기준은 data/source의 QuizData·QuestionData·ResultTypeData·Localization.xlsx입니다.
- tools/data/{validate,build}.py와 lookatyou/{workbook,validate,serialize}.py를 확장합니다. app/lib/features/catalog의 ContentBundle, QuizContent, 코덱·저장소·TextKey 해석을 재사용합니다. 현 0.2.0/schemaVersion 1은 preview에 2개 진단, release에 0개입니다.
- [검토 Excel](LookAtYou_QuestionData_Review_v0.3.xlsx)의 앞 16시트는 첨부 v0.2의 원자료입니다. 마지막 3시트에 Work의 추천 문항, 재현 결과, 31개 사례 대조가 있습니다. 첨부의 LIFE_001은 프로젝트의 life_tactics에 대응합니다. wealth_four는 목록 단계입니다.
- 첨부 LIFE_Q004는 행복, 프로젝트 tq04는 의미입니다. 번호 조인은 금지합니다. 새 파일럿 묶음 후보 DataVersion 0.3.0(이미 사용 중이면 다음 미사용 버전)에 Work_문항추천의 18행을 새 ID lt_vp01…18과 키 life_tactics.question.lt_vp01…18로 들입니다. 표시 순서는 첨부 순서, H=happiness, M=meaning, R=richness입니다. 기존 버전과 응답 기록을 보존합니다. 새 버전에는 새 세트만 활성 문항으로 싣고 QuestionCount=18을 대조합니다. 가중치 1, Reverse=false, 문항·한국어 draft, 번역 미작성은 missing, 부모 비공개·판정 pending을 유지합니다. 나머지 참조 데이터는 같은 버전에 맞춰 복사합니다. 첨부 Excel 전체를 직렬화 입력 폴더에 넣지 않습니다.

## 2. Excel → JSON 계약

기존 네 파일과 열을 활용하고 ResultTypeData.xlsx에 아래 **설정 시트 2개**를 추가합니다. 기존 schemaVersion 1 묶음도 계속 열려야 합니다. 새 schemaVersion 2에만 quizzes/<QuizId>.json의 rule 객체(규칙 필드와 mappings 배열)를 추가하고 catalog·locale·상세의 버전 검사를 함께 갱신합니다. 구버전에 규칙이 없으면 목록·문구/저장된 결과 조회만 허용합니다.

|시트|열과 이 파일럿의 값|
|---|---|
|RuleSets|QuizId, DataVersion, RuleVersion(예 life_rank_v1_preview), Strategy=range_gap_rank, BalanceMaxRange=12, DominanceMinGap=20, TiePriority=happiness,meaning,richness (한 셀의 쉼표 구분 ID 목록을 JSON 배열로 변환)|
|RuleMappings|QuizId, DataVersion, RuleVersion, Kind(balance/dominant/mixed), FirstDimensionId, SecondDimensionId, ResultTypeId. balance는 두 축을 비우고 dominant는 둘째 축만 비움|

(QuizId, DataVersion)별 규칙 세트 하나, 세트 안의 (Kind, FirstDimensionId, SecondDimensionId)는 유일합니다. ResultRuleStatus는 기존 Quizzes에서 읽습니다. 같은 묶음의 활성 축·타입만 참조하고, 우선순위에 각 축이 한 번씩 있어야 합니다. 3축 전략은 균형 1, 단독 3, 순서 있는 혼합 6을 모두 요구합니다. 중복 결과 ID·자기 자신과의 혼합·미등록 전략·범위 밖 임계값을 거부합니다(0 ≤ balance < dominance ≤ 100). 두 번째 진단에 이 전략을 암묵 적용하지 않습니다. 직렬화·검증 실패 시 기존 출력 유지. 앱 에셋 등록·버전 선택까지 확인합니다.

## 3. 진행·채점·판정

1. features/quiz에서 순수 Dart 세션과 채점기를 분리합니다. QuizId/DataVersion으로 묶음을 고정하고 활성 문항만 SortOrder로 진행합니다. 저장 답은 QuestionId → OptionId 한 개입니다. 현재 위치는 QuestionId로 관리하고, 이전 문항에서 답을 교체하면 전체 답 맵으로 재계산합니다. 언어·화면 크기 변경으로 위치나 응답이 초기화되지 않아야 합니다. 두 번 완료해도 같은 입력은 같은 결과입니다.
2. 완료 전에는 응답 수와 빠진 문항을 반환합니다. 수집 시에는 해당 문항의 활성 ScaleId에 속하는 OptionId만 허용합니다. 잘못된 답과 단순 미완료를 구별합니다. 외부 응답 배열을 받을 때 중복 ID를 맵으로 변환하기 전에 검출합니다. 외부 정수 시험값에 bool·소수·문자열을 허용하지 않습니다.
3. 각 문항 척도의 활성 최솟값 L, 최댓값 U, ScoreValue v를 읽습니다. 정방향 x=v, 역채점 x=L+U−v. 현재 1~5점에서 정규값은 (x−1)/4입니다. 일반식은 축별 **100 × Σ[w × (x−L)/(U−L)] / Σw**입니다. 원점수 합이 필요하면 Σ(w×x)를 별도로 제공합니다. 가중치가 0 이하·비유한이거나 척도 폭 0, 필수 축에 문항 없음, 중복 ScoreValue이면 데이터 오류입니다. 세 축의 합은 제한하지 않습니다.
4. 판정은 반올림 전 비교, 표시만 소수 첫째 자리 half-up입니다. 두 언어에서 같은 경계를 보장하도록 소수 설정은 십진수로 정규화해 유리수 분자·분모로 비교합니다(교차곱, 필요 시 BigInt). 첨부 시뮬레이터는 점수를 먼저 소수 첫째 자리로 반올림합니다. 현재 등가중 격자와 12/20에서는 결과가 같지만 다른 가중치·임계값으로 일반화하지 않습니다.
5. range_gap_rank는 점수 내림차순, 동점은 설정된 축 순서로 정렬합니다. 최고−최저 ≤ 12이면 balance, 아니면 1위−2위 ≥ 20이면 dominant, 나머지는 mixed. 해당 키로 아래 Excel 매핑 한 행을 찾아 결과를 반환합니다. 02_ARCHITECTURE의 구 제안(원점수 범위 ≤3, 공동 2위 단독 처리)과 섞지 않습니다. 예를 들어 축 합 (22,18,18)은 새 안에서 tr08입니다.

6. 반환값은 quizId, dataVersion, ruleVersion, resultTypeId, dimensionScores, 판정 경로와 동점 축입니다. formation은 화면용 문자열입니다. 순수 엔진에 문항 수·ID·포메이션·콘텐츠 문구를 넣지 않습니다. 등록한 ScoreMode와 규칙 전략을 조합하고, ResultTemplateId는 표시 계층만 사용합니다. 고점 균형과 저점 균형은 같은 전술과 서로 다른 세 수치를 보여 줍니다. 균형형 설명 예시는 “이번 응답에서는 세 성향의 점수 차이가 작았어요.”입니다. 동점이면 나란히 표시하고 고정 우선순위가 성향의 강도 차이를 뜻하는 표현을 피합니다.
7. 자동 판정은 승인된 출시 규칙에만 허용합니다. pending 규칙의 실행은 개발용 진입점에서 명시적으로 시작한 파일럿/테스트 세션만 허용하고 결과에 미리보기 상태를 표시합니다. 출시 결과·공유 이력과 분리합니다. 실패 시 무작위 결과나 기본 tr10을 반환하지 않습니다.

## 5. Python 시뮬레이터와 Dart 일치 검증

- Python 운영 도구는 생성 JSON을 입력받습니다. 시드·집단 규모·생성 설정·규칙 버전·입력 버전과 해시를 기록합니다. 첨부 스크립트는 기준선 재현용입니다. 그 안의 18개 길이 제한, H/M/R 상수, 행번호로 설정을 읽는 코드, 포메이션 반환 사전을 공통 엔진으로 복사하지 않습니다.
- 기준선 재현은 첨부 Excel의 **원래 문항 순서**와 Python random.Random의 호출 순서, 집단별 표본수·반올림·표집 순서를 고정합니다. 첨부 Python 실행 예: python LookAtYou_Quiz1_Simulator_v0.2.py --input LookAtYou_QuestionData_Draft_v0.2.xlsx --output replay.json. 제공된 JSON과 구조적으로 비교합니다. 새 시뮬레이터는 프로필로 집단 설정을 받습니다. 역문항이 생기면 잠재성향에서 생성한 선호도를 역방향 원응답으로 변환하고, 직선응답 집단은 실제 누른 원응답 그대로 둡니다.
- Python이 생성한 구체적인 QuestionId/OptionId 응답과 기대 분자·분모, 표시값, 결과 ID 또는 오류 코드를 동일 fixture JSON으로 Dart 테스트에 넘깁니다. 언어별 난수열을 맞출 필요가 없습니다. 기대값은 독립 산술과 수작업 예제로도 검산합니다. 두 엔진이 서로 다른 오답을 놓치지 않도록 실제·기대·최초 불일치 입력을 출력합니다.
- 정상 입력에는 10종 매핑 전부, 응답 순서 섞기, 전부 1·3·5(각 축 0·50·100, 모두 tr10), 모든 15,625칸, 공동 선두/공동 2위, 세 축 모두 동점, 두 극단에 몰린 답을 포함합니다. 예: 축점수 (75,75,25)→tr08, (25,75,75)→tr05, (75,25,25)→tr07. 전략 단독 시험은 (62,56,50)→tr10, (62.01,56,50)→tr08, (70,50,45)→tr07, (69.99,50,45)→tr08로 등호와 반올림 시점을 검증합니다.
- 가중 평균 예: 같은 축의 두 문항에 (응답 2, 정방향, w=1), (응답 2, 역방향, w=3)이면 점수 62.5입니다. 역방향 1/3/5→5/3/1, 한 축만 수정 시 다른 축 불변, 표시 순서와 언어 불변을 확인합니다. 문항 수가 다른 시험용 소형 진단도 통과해야 합니다.
- 오류는 incomplete(필수 미응답), invalidAnswer(옵션·척도·ID·자료형 오류), invalidDefinition(잘못된 축·가중치·매핑), unsupportedStrategy, ruleUnavailable, versionMismatch를 구분합니다. 무효 입력은 점수와 결과를 발행하지 않습니다. 구버전 응답을 새 세션에 합치지 않습니다.
- 임계값 실험은 입력 응답을 고정하고 변경 전후 타입 전이표·집단별 변경률·동점 빈도를 비교합니다. 문항 문구만 바꿨을 때 기존 생성기는 뜻을 읽지 않으므로 숫자가 같아도 편집 효과를 검증할 수 없습니다.

## 6. 문항 파일럿과 완료 인수

18문항 추천본은 첨부 원문 대비 유지 5, 수정 10, 교체 3입니다. 행복은 즐거움과 평온, 의미는 목적·가치·기여, 풍요는 새 경험·시점 변화·복합적 여운에 초점을 맞췄습니다. 모두 긍정 방향이라 높은 동의로 몰릴 수 있습니다. 첫 파일럿은 정채점으로 읽기 부담을 줄이고, 동의 쏠림·응답 시간·문장 이해·번역을 관찰한 뒤 필요 시 같은 내용의 반대 방향 문항을 별도 버전으로 비교합니다. 직선응답을 자동 탈락시키거나 성향으로 단정하지 않습니다.

한국어 사용자 10~20명에게 먼저 익명으로 시험합니다. 문항을 자기 말로 풀어쓰기, 실제 생활 여건과 원하는 삶 중 무엇을 떠올렸는지, 비슷하게 읽힌 문항 쌍, 균형형 문구와 자신의 세 점수가 어울리는지, 재미·불편 여부를 기록합니다. 특히 Q05/Q14의 가치 기준, Q04/Q13의 평온, Q08/Q17의 기여를 우선 확인합니다. 반복해 같은 혼동이 관찰되면 근거를 기록하고 수정본을 다시 시험합니다. 소규모 면담과 가상 데이터로 신뢰도·타당도, 문화권 간 동등성, 실제 유형 비율을 확정할 수 없습니다.

**Cursor가 실행하고 결과를 보고할 명령과 인수 조건**

1. D:\AppYou에서 python tools/data/validate.py, python tools/data/build.py, python -m unittest discover -s tools/data/tests를 실행합니다. 설치 환경은 tools/data/requirements.txt를 따릅니다. 같은 입력의 재빌드 결과, 기존 0.2.0 보존, 새 preview 18문항·10종, pending인 life_tactics의 release 제외를 확인합니다.
2. D:\AppYou\app에서 flutter pub get, flutter analyze, flutter test, flutter run -d chrome -t lib/ui_preview.dart를 실행합니다. 작은 모바일 폭과 PC에서 시작 → 이전/수정 → 언어 전환 → 마지막 응답 → 결과 점수·한 개의 타입까지 확인합니다. 같은 답에 화면·Python 결과 ID가 일치해야 합니다.
3. 31개 사례, 전체 격자, 가중치·역채점·불량 데이터, 버전 1 읽기, 미승인 결과의 출시 차단을 자동 검증합니다. 표준 10만 건 재현과 새 번들의 결과는 각각 입력 버전을 붙여 보고합니다. 공통 fixture에서 Dart/Python 불일치 0건, 대표 실패 입력이 의도한 오류를 내야 완료입니다.
4. 변경 파일, 사용 데이터/규칙 버전, 시드, 표본 및 분모, 실행 명령별 성공/실패/미실행, 미해결 사항을 제출합니다. 이번 Cursor 범위는 데이터 계약·공통 엔진·미리보기 연결·검증 도구까지입니다. 출시 전환, 공유 기능, 운영 배포, 두 번째 진단 유형 설계와 사람 대상 파일럿 수행은 별도 작업입니다.
